Общее описание системы
Наименование: hgiohk
Тип приложения: Десктопное приложение (WinForms) для платформы Windows.
Целевая платформа: .NET 10.0 (с поддержкой Windows Forms), также возможно развертывание на .NET 6.0.
Назначение: Система авторизации пользователей с разграничением прав доступа (Администратор / Пользователь) и реализацией капчи в виде drag-and-drop пазла.

Фреймворк	                          .NET 10 (WinForms)

Система сборки	                    MSBuild (через dotnet CLI или VS)
Взаимодействие с данными	          System.Text.Json (сериализация)

Архитектура приложения
Приложение построено по классической архитектуре "Форма + Сервис".

Диаграмма компонентов
UI Слой:

LoginForm — главное окно, отвечает за аутентификацию и сборку пазла-капчи.

AdminForm — панель администратора (управление пользователями).

UserForm — рабочее пространство обычного пользователя.

Program — точка входа.

Слой бизнес-логики (Services):

DatabaseService — статический класс, выполняющий все операции с базой данных (файлом users.json).

Модель данных (Models):

User — структура данных, описывающая объект "Пользователь".

Связи между классами
LoginForm -> DatabaseService (для аутентификации, блокировки, обновления попыток).

AdminForm -> DatabaseService (загрузка списка, добавление, разблокировка).

AdminForm, UserForm -> создаются в LoginForm в зависимости от роли пользователя.

Форма авторизации (LoginForm)
Назначение: Вход в систему и защита от ботов с помощью Drag-and-Drop пазла.
Элементы:
Поля ввода логина и пароля (TextBox).
Кнопка "Войти".
Капча: Панель-мишень (Panel) и 4 части изображения (PictureBox).
Кнопка "Проверить капчу".
Логика работы:
Пользователь вводит логин и пароль.
Собирает пазл (перетаскивает части в мишень).
Нажимает "Проверить капчу".
Если сборка верна — капча считается пройденной (isCaptchaSolved = true).
Если неверна — счетчик failedAttempts увеличивается. При 3 неудачных попытках аккаунт блокируется.
Нажимает "Войти". Проверяется статус капчи, корректность логина/пароля, и статус блокировки.

Панель администратора (AdminForm)
Назначение: Администрирование пользователей.
Элементы:
DataGridView для отображения всех пользователей.
Поля ввода логина, пароля и выбора роли для добавления нового пользователя.
Кнопки "Добавить" и "Снять блокировку".
Логика работы:
Загружает данные из DatabaseService.LoadUsers(). Поле "Пароль" скрыто.
"Добавить": Проверяет заполнение полей, уникальность логина, создает нового пользователя.
"Снять блокировку": Снимает блокировку с выбранного в таблице пользователя.

Форма пользователя (UserForm)
Назначение: Стартовое окно для обычного пользователя.
Функционал: Отображает приветственный текст. Является заглушкой (может быть расширена).

Логика безопасности (Авторизация)
Проверка капчи: Обязательна перед входом. Реализована как проверка координат каждой части картинки относительно панели-мишени (допустимое отклонение ±5 пикселей).

Неудачные попытки:
Счетчик failedAttempts хранится в памяти формы.
При неверном логине/пароле или неверной капче счетчик увеличивается.
При достижении 3 неудачных попыток вызывается DatabaseService.BlockUser(login), после чего ввод данных блокируется.
Восстановление доступа: Сброс блокировки возможен только администратором через AdminForm (метод UnblockUser).
Роли: При успешной аутентификации проверяется поле Role для открытия соответствующей формы.

 Инструкция по развертыванию (Deploy)
Требования: Установленный .NET SDK версии 10.0 (или 6.0, если используется net6.0-windows).
Сборка:

bash
dotnet build -c Release

Публикация (если нужен один exe):

bash
dotnet publish -c Release -r win-x64 --self-contained false

Структура развертывания: Скопировать папку bin\Release\net10.0-windows\ на целевую машину.
Файлы изображений: Убедиться, что файлы 1.png, 2.png, 3.png, 4.png находятся в одной папке с исполняемым файлом hgiohk.exe.

Известные ограничения
Пароль хранится в открытом виде (несмотря на UseSystemPasswordChar в интерфейсе, в JSON он не шифруется). Требуется внедрение хеширования (например, SHA256).
Счетчик попыток для авторизации при неверном логине хранится в памяти и не переносится в файл users.json (кроме метода UpdateFailedAttempts).
Капча не является стойкой криптографической защитой, так как координаты тайлов проверяются только в клиентской части.
